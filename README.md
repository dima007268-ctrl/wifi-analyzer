# Wi-Fi анализатор на Python (Windows)

Учебный проект: сканер Wi-Fi сетей вокруг, в котором путь от Python до Windows пройден и написан вручную.
Вместо готовых `subprocess` и `ctypes.windll` используются собственные упрощённые версии,
написанные по исходникам стандартной библиотеки Python, вплоть до границы с языком C.

## Что умеет

- запускает **свежее сканирование эфира** через функцию Windows `WlanScan` (`wlanapi.dll`), а не читает устаревший кэш;
- получает список сетей через `netsh wlan show networks mode=bssid`;
- **разбирает** текстовый вывод `netsh` в список словарей (парсер на регулярных выражениях);
- выводит таблицу: имя сети, сигнал в % и dBm, канал, диапазон (2.4 / 5 ГГц), сортировка по силе сигнала;
- повторяет сканирование заданное число раз с паузой.

## Пример вывода

```
Сканирование 1/3
SSID                  Сигнал   dBm  Канал  Диапазон
----------------------------------------------------
HomeNet-5G              100%   -50     36     5 ГГц
HomeNet                 100%   -50     13   2.4 ГГц
Neighbor-1               95%   -53     11   2.4 ГГц
Neighbor-2               35%   -83      6   2.4 ГГц
<скрытая>                10%   -95    149     5 ГГц
```

## Требования

- Windows 10 / 11 с Wi-Fi адаптером;
- Python 3.8 или новее (используется оператор `:=`);
- **русская локализация Windows**: парсер ищет русские названия полей (`Сигнал`, `Канал` и т.д.);
- включён доступ к расположению: *Параметры → Конфиденциальность и защита → Расположение*,
  включая «Разрешить классическим приложениям доступ к расположению». Без этого Windows
  показывает программам только сеть, к которой вы подключены.

Сторонние библиотеки не нужны, только стандартная библиотека Python.

## Запуск

```
python wi_fi_proj.py -r 3 -t 5
```

| Аргумент | Что значит | По умолчанию |
|---|---|---|
| `-r`, `--retries` | сколько раз сканировать | 5 |
| `-t`, `--timeout` | пауза между сканированиями, секунд | 10 |

Справка по аргументам: `python wi_fi_proj.py --help`.

## Как это устроено

Путь одного сканирования:

```
wi_fi_proj.py  main()
│
├── 1. wlan_scan.trigger_scan()              ← свежее сканирование эфира
│      └── my_ctypes.my_windll.wlanapi       ← загрузка wlanapi.dll
│            └── _ctypes (C)                 ← граница Python | C
│                  └── wlanapi.dll → служба Windows «Автонастройка WLAN» → адаптер
│
├── 2. run_modul.my_run(["netsh", ...])      ← запуск netsh и захват вывода
│      └── my_popen.MyPopen
│            └── _winapi (C)                 ← граница Python | C
│                  └── kernel32.dll → процесс netsh.exe → текст через трубы
│
├── 3. parser_networks_windows(текст)        ← текст → список словарей
│
└── 4. print_networks(сети)                  ← таблица на экран
```

## Модули подробно

### `my_popen.py` — своя версия `subprocess.Popen`

Запускает внешнюю программу и подключает к ней трубы, чтобы прочитать её вывод.
Построен напрямую на `_winapi`, встроенном C-модуле Python.

| Метод | Что делает |
|---|---|
| `_get_handles` | создаёт трубы (`CreatePipe`) для stdin, stdout, stderr |
| `_make_inheritable` | делает копию конца трубы, которую можно передать дочернему процессу (`DuplicateHandle`) |
| `_execute_child` | заполняет `StartupInfo` и запускает программу (`CreateProcess`) |
| `communicate` | читает трубы до конца, ждёт завершения процесса, превращает байты в текст |
| `poll` | возвращает код завершения процесса (`GetExitCodeProcess`) |
| `__enter__` / `__exit__` | поддержка `with`, закрытие номерка процесса |

### `run_modul.py` — своя версия `subprocess.run`

Обёртка над `MyPopen`: принимает аргументы, расставляет трубы для `capture_output`,
запускает процесс и возвращает объект-отчёт `CompletedProcess` (`args`, `returncode`, `stdout`, `stderr`).
При `check=True` и ненулевом коде выбрасывает `CalledProcessError`.

### `my_ctypes.py` — своя версия `ctypes.windll`

| Класс | Роль |
|---|---|
| `LibraryLoader` | «справочное бюро»: по имени (`my_windll.wlanapi`) загружает DLL и запоминает её |
| `MyWinDll` | «представитель DLL»: хранит номерок загруженной библиотеки и находит в ней функции по имени |

Оба класса используют `__getattr__` и кэширование через `setattr`.
Из чужого кода остался только модуль `_ctypes` (C): `LoadLibrary`, `CFuncPtr`, `_SimpleCData`.

### `wlan_scan.py` — свежее сканирование эфира

Функция `trigger_scan(wait=4)`:

1. `WlanOpenHandle` — открыть сеанс со службой Wi-Fi;
2. `WlanEnumInterfaces` — найти Wi-Fi адаптер и его GUID;
3. `WlanScan` — попросить адаптер просканировать эфир;
4. `WlanFreeMemory`, `WlanCloseHandle` — уборка (в блоках `try / finally`);
5. подождать `wait` секунд, пока адаптер закончит.

Структуры Windows (`GUID`, `WLAN_INTERFACE_INFO`, `WLAN_INTERFACE_INFO_LIST`) описаны через `ctypes.Structure`
в точности по документации Microsoft. Функции `wlanapi` возвращают код ошибки (`0` — успех),
поэтому каждый вызов проверяется через `if result != 0`.

### `wi_fi_proj.py` — главный файл

| Функция | Что делает |
|---|---|
| `scan_wifi` | определяет ОС и вызывает сканер для Windows |
| `scan_wifi_windows` | `trigger_scan()` → `netsh` → парсер |
| `parser_networks_windows` | разбирает текст `netsh` в список словарей |
| `print_networks` | таблица, сортировка по сигналу, перевод % в dBm |
| `parse_arguments` | аргументы командной строки (`argparse`) |
| `main` | цикл сканирований с паузой |

## Граница Python и C

| Своё (Python) | Чужое (C, внутри Python) | Windows |
|---|---|---|
| `MyPopen`, `my_run` | `_winapi` | `kernel32.dll` |
| `LibraryLoader`, `MyWinDll` | `_ctypes`, libffi | `wlanapi.dll` |
| парсер, таблица, `main` | `re` (ядро `_sre`) | — |

## Известные ограничения

- работает только на Windows с русской локализацией;
- `MyPopen` склеивает команду через пробел, без кавычек: аргументы с пробелами не поддерживаются;
- `MyPopen.communicate` читает stdout и stderr по очереди, а не одновременно:
  при очень большом выводе в stderr возможно зависание (в оригинале для этого используются потоки);
- нет таймаутов и передачи данных на вход программы (`input`);
- `MyWinDll` по умолчанию считает, что функции возвращают 32-битное число (`c_int`);
- `trigger_scan` использует только первый Wi-Fi адаптер и ждёт фиксированное время.
